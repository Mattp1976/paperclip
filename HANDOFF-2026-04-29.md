## What's still broken or unverified

### 1. Orchestra → wakeup-with-issue-context bridge (today's main finding)

When the orchestra assigns an issue to an agent, no wakeup gets enqueued
with the issue's context. So the agent never automatically picks up the
work. I had to manually invoke the agent, and even then it ran with an
empty context and spent its run trying to figure out which task it was
supposed to do.

**Fix needed:** in the orchestra service, when an issue is assigned to an
agent, enqueue an agent_wakeup_request with `payload.issueId` set. The
agent's wakeup handler should read that and start working on the specific
issue.

This is the **single highest-leverage engineering task** for tomorrow. It
turns the verified-working pieces into an actual end-to-end demo.

### 2. Prod Postgres mismatch (still open)

Yesterday's "two physical Postgres servers" finding was reproduced today
even after switching the prod `DATABASE_URL` to the public proxy URL. The
prod server's better-auth signs in users that don't exist in the proxy DB
when queried from outside. Same hostname, different data depending on
where you connect from.

**Likely root cause:** Railway's TCP proxy routes connections from the
internal network differently from external connections. The "Postgres"
service we see on the canvas might have an orphan instance still running
behind it.

**Tomorrow's first move (if pursuing prod):** delete the Postgres service
in the Railway UI, recreate it fresh, redeploy. This was Phase 2 of
yesterday's plan. Took the local-first path today instead because it had
fewer unknowns.

### 3. Better-auth password sign-in via API for matt's account

Still rejects with `INVALID_EMAIL_OR_PASSWORD` despite the hash matching
when verified locally. Use the freshly bootstrapped account approach
instead (sign-up creates a working credential). The matt account password
issue is deferrable.
