By end of today, **one stranger should be able to land on orqestra.run, sign up,
ask for an outcome, watch it succeed, and receive a finished deliverable.**

foundation for everything else. Nothing else this week unlocks until that's
true.

We have not yet achieved that on prod. The brand is good, the landing is good,
the codebase is largely there. What's missing is **proof the system works for
someone who isn't us**.

and tell me:

**Done when:** I have a clear picture of the prod DB topology.

### Phase 2 · Clean prod database reset (30-45 min, you click, I narrate)

We pick the path based on Phase 1:

**Path A — One Postgres but stale data (most likely).** Reset the existing
Postgres in place via Railway's "Database" tab, or wipe + recreate. Result:
empty `railway` DB, ready for fresh migrations.

**Path B — Two Postgres services.** Delete the orphan (the one nobody is
using — we identify which by service ID and last-deployed timestamp). Result:
single canonical Postgres.

**Path C — Something else** (replica, failover, custom routing). Untangle
based on what we find.

For all paths, the *paperclip* service container stays. We just give it a
fresh DB to write into. On next start the server will run drizzle migrations
and create empty tables.

**Done when:**
- Exactly one Postgres in the project.
- `postgres.railway.internal` from inside the container AND
  `trolley.proxy.rlwy.net` from outside resolve to the **same physical
  instance** (verified by `inet_server_addr()` matching from both ends).
- The paperclip service has redeployed against the fresh DB.
- `https://www.orqestra.run/api/health` returns 200 with `bootstrapStatus:
  "bootstrap_pending"` (no admin yet, fresh DB).

   sign-up link.

   in. You become the only `instance_admin` on prod.
3. I verify your session works against the company-listing endpoint
   (which yesterday returned `[]` because of the DB mismatch).

**Done when:** You can hit `https://www.orqestra.run/api/companies` from your
browser session and get back an empty list (200 OK, `[]` because no companies
yet, but no 401/403).

### Phase 4 · One outcome, end to end, on prod (20 min, I do)

This is the actual proof.

1. I install **Solo Consultant** — the three-agent template — onto your prod
   account via the API.
2. I create one outcome via the API: *"Produce a one-page intelligence brief
   on the future of agentic AI."*
3. The planner returns a costed plan. I approve it.
4. The agents run. I watch the heartbeat run logs.
5. The reviewer reviews. The assembler assembles. A deliverable lands on the
   outcome detail page.
6. Verification:
   - Did every step succeed?
   - What was the wall-clock time?
   - What did it cost?
   - Is the deliverable actually readable?

If anything fails, I diagnose at the *exact* failed step (planner timeout,
agent not found, Claude Code CLI missing in container, etc.) and we triage
from there.

**Done when:** The outcome detail page on prod shows a green "Done" status
with a deliverable I can show you. **OR** we have a precise, named, captured
failure to fix in Phase 4b before continuing.
