# Delegation audits

A weekly-or-so ritual. Load the CEO with a real multi-step task, watch the
full chain, and record every rough edge.

This is not a focus group — it's an operator sitting with their own product,
doing real work, taking notes. One notebook per audit. `_template.md` is
the blank form. Copy it to `YYYY-MM-DD.md` at the start of each audit.

## Why

The delegation loop is the wedge. The only way to tell whether it's
actually clean is to run it end-to-end with intention and log the truth.

## Cadence

Week 2 of the 30-day plan: one audit on the Monday, time-boxed to a day.
After that, cadence is fluid — run one whenever the chain has changed
substantially (new agents, new review card, new verbs, new graph).

## How to run one

1. Copy `_template.md` to `YYYY-MM-DD.md`.
2. Pick one realistic multi-step brief. "Prep a market scan on UK legal tech" is
   good: research → competitors → memo → executive summary.
3. Hire (or reuse) a CEO agent. Prompt verbatim in the audit note.
4. Start the chain. Don't touch anything for 60 seconds unless it's clearly stuck.
5. Every sigh, hesitation, wrong label, missing button → a line in the watch log
   or rough-edges list.
6. At the end, fill in the verdict paragraph. Be blunt. If the loop is rough, say so.
7. Open issues or broken-windows entries for each rough edge.

## What to watch for

- **Verb inconsistency** (VOICE.md rule 9 — `Route to` is the verb).
- **Invisible state** — the operator doesn't know where the work is, or what the
  agent decided and why.
- **Implicit routes** — the chain happened, but you can't see who-did-what
  afterwards without digging into logs.
- **No review surface** — child agent finished, parent doesn't know, operator
  never got the 30-second decision card (#20).
- **Dead ends** — an agent got stuck and nothing got routed back to the operator.
- **Cost opacity** — you can't tell whether the chain cost £0.01 or £8.
- **Output opacity** — you can see it ran, but can't easily see what it produced.
